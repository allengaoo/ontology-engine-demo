# demo-supplier

本demo 是公众号对应的一个java demo,模拟使用开源组件来实现本体的多跳查询和对外写入的过程.

## 数据库和中间件

采购库、合同库都是 PostgreSQL 16。

采购库存采购单的当前供应商、更换单状态和审计。

合同库存同一张采购单对应合同的对方和写入次数。更换单状态写在采购库。两个库一起提交，或一起退回。

Seata 2.0.0 只包这两个库，分布式事务使用 XA。Java 客户端是 `io.seata:seata-all:2.0.0`。采购库和合同库各向 TC 注册一个分支。两边都准备好，TC 才通知提交。通知、Kafka、Elasticsearch、Doris 不注册分支。

Elasticsearch 存采购单文档，按 `factory_id` 滤出工厂的采购单。确认用这份结果看采购单在不在查找里，不拿文档上的供应商当当前值。Doris 的交货记录按月存放，确认时按供应商分组汇总准时率；提交成功后再更新采购单对象表。Kafka 在两个库提交成功之后传递编辑。供应商通知由程序里的 sqlite 模拟，不进这次提交。

## 端口

全部绑在 `127.0.0.1`。

| 服务 | 端口 |
| --- | --- |
| 采购库 | 5434 |
| 合同库 | 5433 |
| Elasticsearch | 9200 |
| Kafka | 9092 |
| Seata | 8091 |
| Doris 查询 | 9030 |

用户和口令都是 `ont`，只给这套容器。

## 运行

需要 JDK 17,并在本地部署docker, 以及启动相应的开源组件镜像

```bash
docker compose up -d
./mvnw -q compile exec:java
```

终端会打印这次查找、每次拒绝、两个库的准备和提交、通知超时、补记和追平。全部检查通过时退出码为 0。

Doris 的 BE 第一次起来要1到2分钟，程序会等它变为 Alive。官方启动脚本要求 `vm.max_map_count` 达到 2000000，并要求关闭交换分区。compose 在容器启动前放宽这两项检查，并把堆限制在容器内存以内。

停掉并删除数据：

```bash
docker compose down -v
```

## 检查

查找：Elasticsearch 返回采购单 17 和 18。Doris 分组后低于 90% 的只有乙，比率是 0.82，每个供应商 12 行交货记录。

1. 新供应商准时率不低于 90%：结果为拒绝，两个库的供应商和写入次数不变。
2. 年采购额超过 100 万：采购员确认后，更换单为待主管确认，两个库不写。
3. 主管确认：两个库的供应商变为乙，写入次数为 1，状态为待通知。消费者暂停期间，Elasticsearch 文档仍是甲。
4. 再次确认：拒绝，写入次数仍为 1。
5. 通知失败：状态保持待通知。重发成功后状态为已更换，两个库写入次数仍为 1，门户调用次数为 2。随后文档变为乙，状态为已更换。
6. 年采购额 10 万的 P-18：采购员直接写两个库。把门户标成已送达、但不调用通知，再补记，状态变为已更换，调用次数不变。

另外两件：两个库都完成 XA prepare 之后，全局事务在提交前失败，两边的探测行都退回 0。同一条编辑应用两次，第二次不改文档。
