# 文章 062：更换供应商

工厂 7 号的采购单 P-17，把供应商从甲换成准时率 82% 的乙。采购库和合同库一起提交，或者一起退回。通知失败时，更换单停在待通知。门户已经送达、本地还是待通知时，只补记状态。

## 组件

| 容器 | 作用 |
| --- | --- |
| purchase-db、contract-db | 两个业务库 |
| seata | 事务协调器的位置。Python 没有能驱动 Seata AT 的客户端，提交用 PostgreSQL 的 `PREPARE TRANSACTION` |
| elasticsearch | 采购单文档。确认更换不读它 |
| kafka | 提交成功之后的编辑 |
| doris-fe、doris-be | 交货记录上的准时率，以及追平后的采购单对象表 |

端口只绑在 `127.0.0.1`。采购库是 5434，合同库是 5433，避开本机已经占用的 5432。库口令 `ont` 只给这套本地容器。

## 运行

```bash
docker compose up -d
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python simulate.py
```

Doris 的 BE 第一次起来要一两分钟。`simulate.py` 会自己等。官方启动脚本还要求把 `vm.max_map_count` 调到 200 万并关掉交换分区；compose 里把这两项检查放宽，并把堆降到本机容器放得下的大小。

停掉并清数据：

```bash
docker compose down -v
```

## 断言

1. 新供应商准时率不低于 90% 时拒绝，两个库都不写。
2. 年采购额超过 100 万，采购员确认只把更换单改成待主管确认。
3. 主管确认后，两个库一起变成乙，状态为待通知。此时消费者暂停，文档仍是甲。
4. 再次确认被拒绝。
5. 通知失败停在待通知；重发成功才变成已更换，两个库的写入次数仍是 1。
6. 另一张未超额的单：门户已有送达记录，补记为已更换，不再调用通知。

另外检查：合同库语句失败时，采购库的预提交也会退回。同一条编辑应用到副本两次，结果相同。
