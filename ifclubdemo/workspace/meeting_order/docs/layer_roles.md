# docs/layer_roles.md

## 页面层 (Page Layer)

负责用户界面展示和交互逻辑。页面组件应该只处理 UI 相关的事情，比如渲染表单、显示列表、响应点击事件等。它们不应该直接访问数据库或执行业务规则检查。

- **职责**：
  - 渲染页面内容
  - 处理用户输入
  - 调用服务层方法
  - 显示反馈信息

- **不做什么**：
  - 不直接操作数据库
  - 不编写业务逻辑
  - 不进行数据验证

## 规则检查层 (Rule Checking Layer)

负责执行所有业务规则验证。这个层确保所有的操作都符合预定的业务规范，如时间范围检查、会议室是否可用等。

- **职责**：
  - 验证输入参数的有效性
  - 检查时间范围合理性
  - 确保没有时间冲突
  - 验证会议室状态

- **不做什么**：
  - 不处理数据持久化
  - 不管理页面状态
  - 不直接与数据库交互

## 数据存取层 (Data Access Layer)

负责与数据库进行交互，包括读取和写入数据。它提供了统一的数据访问接口给上层使用。

- **职责**：
  - 提供数据的增删改查功能
  - 封装数据库操作细节
  - 实现数据模型到数据库记录的映射

- **不做什么**：
  - 不包含业务逻辑
  - 不处理页面渲染
  - 不执行规则检查

## 对外接口层 (API Interface Layer)

定义了系统对外提供的接口规范，包括请求格式、响应结构以及错误处理机制。它是前端与后端之间的桥梁。

- **职责**：
  - 定义 RESTful API 接口
  - 处理 HTTP 请求和响应
  - 统一错误码和消息格式
  - 控制访问权限

- **不做什么**：
  - 不实现具体业务逻辑
  - 不直接操作数据库
  - 不关心页面如何展示数据
