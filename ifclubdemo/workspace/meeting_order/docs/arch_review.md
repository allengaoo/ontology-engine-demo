# 架构评审文档

## 项目概述

这个项目是一个会议室预订系统，支持用户查看会议室信息和预订会议。整个系统分为前端和后端两部分，采用分层架构设计，便于维护和扩展。

## 前后端结构

### 后端架构

后端使用 Python 编写，主要由以下几层组成：

1. **模型层 (`models`)**
   - 定义了两个核心数据模型：`Room` 和 `Booking`。
   - `Room` 包含 id、name、capacity 和 is_active 字段。
   - `Booking` 包含 id、room_id、title、booker、start_at 和 end_at 字段。

2. **模式层 (`schemas`)**
   - 定义了请求和响应的数据格式。
   - `CreateBookingRequest` 用于接收创建预订的请求参数。
   - `BookingResponse` 用于返回预订结果。

3. **领域逻辑层 (`domain`)**
   - 实现业务规则校验，如检查时间有效性、是否重叠、房间是否激活等。
   - 提供一系列验证函数来确保数据符合业务规范。

4. **仓储层 (`repositories`)**
   - 抽象出 `MeetingRepository` 接口，定义了基本操作方法。
   - 具体实现为 `SqliteRepository`，负责与 SQLite 数据库交互。
   - 使用工厂模式管理数据库初始化和获取仓库实例。

5. **服务层 (`services`)**
   - 调用领域逻辑进行复杂业务处理。
   - 协调仓储层完成数据持久化。

6. **API 层 (`api`)**
   - 定义 RESTful 接口，对外暴露功能。
   - 使用 FastAPI 框架构建，支持异步请求处理。

### 前端架构

前端基于 React 构建，遵循单页应用原则，通过 API 与后端通信。所有组件都位于 `frontend/src` 目录下，避免使用相对路径引用。

## 支撑 30B 场景的关键工程手段

为了支撑大规模并发场景（30B），我们采用了以下关键工程手段：

1. **分层架构设计**
   - 将不同职责分离到不同层级，提高代码复用性和可测试性。
   - 易于横向扩展各层的功能。

2. **依赖注入机制**
   - 利用工厂模式动态创建仓储实例，降低模块间耦合度。
   - 支持多种存储后端切换（目前仅支持 SQLite）。

3. **异步非阻塞 I/O**
   - 后端使用 FastAPI 异步特性提升吞吐量。
   - 减少等待时间，提高响应速度。

4. **缓存策略**
   - 对频繁访问的数据（如会议室列表）实施缓存机制。
   - 减少数据库查询压力，加快响应速度。

5. **限流与熔断**
   - 在 API 层加入速率限制，防止恶意请求冲击服务器。
   - 设置超时控制和降级策略，保障系统稳定性。

6. **日志监控**
   - 记录关键操作日志，便于问题追踪。
   - 集成监控工具实时观察系统性能指标。

7. **安全防护**
   - 输入参数严格校验，防范 SQL 注入等攻击。
   - 时间范围合法性检查，确保预订时间合理。

这些措施共同作用，使得系统能够稳定运行在高负载环境下，满足 30B 用户同时使用的场景需求。
